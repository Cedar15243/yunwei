# V9 全功能与市场产品化审计

审计日期：2026-07-31
审计对象：`codex/v9-ops-platform`、V9 完整规格、Android 眼镜端、Supabase/Edge Function、管理 Web、专家协同 Web/服务和 Air3 交付链。
审计目标：判断 V9 是否可以继续开发、哪些功能必须调整，以及达到可销售、可部署、可持续运营产品所需的门槛。

## 1. 执行结论

**结论：V9 产品方向可以继续，当前实现不可发布，也不应按原范围平铺开发。**

建议继续的前提是把产品定位收敛为“AI 原生、免手操作、可审计的工业现场执行层”，首发聚焦楼宇/HVAC/设施运维，并接入客户现有 CMMS/EAM/工单与 MDM。不要在 V9 内重造完整 FSM、调度、库存、计费和设备管理平台。

当前市场就绪度为 **34/100（内部审计评分，不是行业认证）**：V8 眼镜主流程、专家协同和测试基础较强；V9 的账号/设备、事件同步和管理台已有骨架；但技能运行时、项目记忆、声纹、知识库、企业身份、生产部署和 V9 Air3 证据尚未形成闭环，并存在实际路由、任务状态和密钥边界缺陷。

评分构成：眼镜现场执行 `14/20`，项目/任务/证据闭环 `7/20`，AI Skill/知识/记忆 `3/20`，企业身份/设备/安全 `3/15`，云端运营/集成 `3/15`，质量/SRE/发布 `4/10`。每项只按当前可复现证据计分，规格、计划、mock 和未部署代码不计为完成。

发布判定：**NO-GO**。
开发判定：**CONDITIONAL GO**，必须按第 10 节的顺序和停止条件推进。

## 2. 市场基准与产品边界

| 市场能力 | 行业基准 | V9 当前状态 | V9 应达到的目标 |
|---|---|---|---|
| 免手现场执行 | RealWear、TeamViewer 已形成工业眼镜、分步工作流、远程协助和规模部署 | V8 HUD/拍照/语音/专家链路有实机证据 | 保持低操作优势；形成单任务、单证据链、弱网可恢复闭环 |
| 工单/资产/历史 | Dynamics 365、ServiceNow 覆盖工单、资产、SLA、调度、历史、移动执行 | 本地 TaskSession 和云端基础表，缺资产/SLA/外部工单合同 | 做“轻工单执行模型 + CMMS/EAM 连接器”，不重做调度/库存/计费 |
| 数字工作指引 | TeamViewer、Augmentir 支持版本化指导、检查、培训 | 霍尼韦尔场景为本地硬编码；Skill 目录为 `PLANNED` | 云端结构化技能、模拟验证、审核、发布、分配、快照、观测、回滚 |
| AI Agent/助手 | Augmentir、ServiceNow 已将 AI 连接到人员、流程和数据 | 现有 AI 可对话，但无服务端 SkillRuntime/ExecutionContext | 每轮可证明使用的技能、知识、记忆和证据；输出动作受应用确认 |
| 知识治理 | 企业平台强调内容、流程、权限和来源 | 华方知识库尚无真实实体/API/工作台 | 文档/案例草稿、审核、发布、版本、权限、引用、过期和归档 |
| 设备治理 | RealWear Cloud 有固件、应用、Wi-Fi、安全、SSO、角色和分析 | 仅设备表、一次性凭据 API、受管配置读取 | 接入 Android Enterprise/OEM MDM；V9 只管理业务绑定、凭据和同步健康 |
| 离线与同步 | 主流 FSM 宣称移动离线，但公开移动端反馈显示慢、等待和不稳定仍是痛点 | 有本地事件队列骨架，尚未接业务回调和云端部署 | 本地先落盘、幂等送达、失败钻取、媒体续传、状态不假成功 |
| 企业集成 | TeamViewer/ServiceNow/Augmentir 均强调 API 和 ERP/CMMS 集成 | 无正式连接器框架 | 版本化 Webhook/API、外部 ID、幂等、映射、重放、审计和沙箱 |
| 企业身份与合规 | SSO、角色、审计、保留策略是采购门槛 | Supabase Auth + 基础 profile/RLS | OIDC/SSO 起步，SAML/SCIM 预留；组织/项目最小权限、审计和数据治理 |
| 项目记忆 | 竞品多强调历史/知识，较少提供可见、可撤销的项目级 AI 指令 | 规格完整，实现缺失 | 这是 V9 核心差异化：来源、条件、版本、撤销、跨项目隔离和人工提升 |

市场资料与来源见 `design/research.md`。

对齐与超越的边界应明确：企业身份、设备治理、离线、审计、部署和连接器只需达到采购基线；完整 FSM/MDM 不参与正面竞争。V9 必须在三点上超越：眼镜端更少操作和更快反馈、每轮 AI 技能/知识/证据可证明、项目级记忆可见且可撤销。没有实测数据前，这三点只能称为目标，不能写成市场承诺。

## 3. 产品化调整

### 3.1 必须保留并强化

1. 冻结现有眼镜首页、HUD、按钮位置、相机和专家页；V9 只增强既有入口后的行为和数据闭环。
2. 保留小叮当单轮唤醒；声纹模式与其互斥，失败不回退、不执行、不上传。
3. 项目/任务作为所有对话、证据、技能、知识、专家和审计的共同主键。
4. 服务端真实解析 Skill、知识和项目记忆；客户端只提交身份、任务和本轮输入。
5. 项目结束摘要、项目记录、显式历史恢复和项目指令版本管理。
6. 现有专家协同继续独立运行，V9 只关联会话、批注和任务步骤。

### 3.2 必须调整

1. **声纹从主线依赖改为可选增强。** 先交付统一音频协调器和双语音状态机，再接声纹。声纹只做已登录/绑定设备上的操作门，必须有实体键/屏幕替代路径、重放防护、同意/撤销和供应商 SLA。达不到延迟、误拒、误受和噪声门槛时，不进入 GA 默认功能。
2. **账号管理接入企业身份。** Supabase Auth 可用于试点，但市场版要支持 OIDC，预留 SAML/SCIM；不要自研密码、MFA 和企业目录全套能力。
3. **设备管理不扩成 MDM。** V9 负责设备业务身份、操作者绑定、凭据、策略版本和同步健康；固件、Wi-Fi、Kiosk、应用分发接 Android Enterprise/OEM MDM。
4. **Skill 不是 Prompt 编辑器。** 使用受限结构化包：适用范围、条件、步骤、阈值、风险、知识范围、允许动作、输出约束和测试集。发布版本不可变，支持评估、灰度和回滚，不允许下发任意代码或秘密。
5. **知识库不是文件列表。** 必须有解析状态、来源、版本、有效期、权限、审核、引用、重复检测、过期提醒和案例提升流程。
6. **补齐轻量工单/资产合同。** 增加 `external_work_order_id`、资产、位置、优先级、SLA、负责人、技能要求、步骤、材料使用（可选）、结果和回写状态；调度、库存和计费交由外部系统。
7. **生产版应用标识策略调整。** V9 审计/候选包继续用独立 `applicationId` 保护稳定版；正式 GA 后必须使用一个稳定生产包名、正式签名和可升级链路。不能每次市场升级都新装一个包。
8. **演示数据与正式数据隔离。** 多行业流程只能作为明确标注的模板/沙箱；没有真实发布和授权时不出现在正式可用列表。

### 3.3 延后或删除

- 延后完整排班、路线优化、库存、采购、计费、客户门户和完整 CMDB。
- 延后 1:N 声纹识别、全天候语音采集和跨项目自动记忆。
- 删除眼镜端复杂 Skill/知识编辑器设想；眼镜只启用、关闭、查看版本和状态。
- 删除任何本地“已启用/已同步/已入库”假状态和正式环境 fixture/mock。

## 7. 市场版最小产品包

V9 GA 应由五个明确产品面组成：

1. **Glasses Client**：任务、证据、AI 指导、专家协同、结束/恢复、设置和可选声纹。
2. **Execution Service**：身份/授权、`ExecutionContext`、SkillRuntime、知识检索、AI 输出校验和动作确认。
3. **Ops Control Center**：人员/角色、设备、项目任务、媒体、同步异常、专家记录、审计和指标。
4. **Skill & Knowledge Studio**：技能/知识草稿、测试、审核、发布、分配、评估、回滚和版本引用。
5. **Integration Gateway**：CMMS/EAM/工单/资产/MDM 的版本化 API、Webhook、映射、幂等、重试和审计。

## 8. 市场发布质量门槛

### 功能闭环

- 一个真实楼宇/HVAC 任务从外部工单/新建项目开始，完成身份、技能、知识、语音/图片、AI、维修步骤、专家、结束摘要、云端记录和结果回写。
- 所有正式入口都有真实数据、授权、写入、失败、重试、审计和撤销；无假成功。
- 新项目不继承旧项目结论；显式恢复准确恢复原任务、技能快照和步骤。

### 体验与性能

- 本地按键/模式/UI 状态反馈 p95 < 150ms。
- 服务端上下文构建 p95 < 100ms，知识检索 p95 < 150ms；Skill 启用后的首 token p95 相比通用 AI 劣化 <= 150ms。
- 参考网络下 AI 首 token绝对 p95 目标 <= 2.5s；超时显示阶段和恢复动作。
- 事件最终送达率 >= 99.9%，媒体在重试后的最终成功率 >= 99.5%，不能丢本地证据。
- 真人中文命令在定义噪声档位、口罩/PPE 和不同说话人下完成识别测试；不得用合成音频替代市场验收。Air3 无法匹配工业设备宣传的 100dBA 时，应明确产品适用噪声范围并保留实体键。
- 声纹 GA 前需给出误受率、误拒率、重放攻击、网络失败和 3 秒 p95 数据；达不到门槛则保持关闭/试验状态。
- 20 分钟及长流程无 crash、ANR、持续录音、不可恢复抢麦或热状态异常；内存、温度、电量和帧时间不劣于同设备 V8 基线。

### 企业与安全

- 生产 APK 不含供应商密钥、共享 API key、声纹模板或原始声纹音频；使用正式签名和稳定升级链。
- 组织/项目/角色越权、设备撤销、一次性凭据、审计不可篡改、媒体短签名、保留/删除、备份恢复和灾难恢复均有测试。
- 至少完成威胁建模、依赖/秘密/SAST 扫描、API 越权测试、提示注入/知识投毒测试和第三方渗透测试计划。
- 根据销售区域准备数据驻留、个人信息/生物识别同意、处理协议和删除机制；合规结论需要法务/安全负责人确认。

### 试点与商业结果

- 先以 5-20 台设备、2-3 个现场、连续 4 周进行受控试点。
- 试点目标建议：任务完成率、首次修复率、MTTR、专家升级率、证据完整率、AI 建议采纳率、同步失败恢复时间和一线满意度。
- “降低 MTTR/提升首次修复率”等市场承诺只能使用试点真实数据，不引用竞品宣传数字代替。

## 9. 继续开发的停止条件

出现以下任一情况，停止扩页面并回到当前层修复：

1. 无法提供真实 Supabase/云服务器/供应商配置，或无法建立安全的设备凭据投放通道。
2. 当前垂直任务不能形成真实项目、资产、技能、知识、证据、结束和恢复闭环。
3. Skill 仍只改变 UI 标题或客户端提示，不能在服务端运行审计中证明生效。
4. 任一入口只能依靠 mock/fixture/静态成功文案工作。
5. 声纹或 AI 增加明显延迟、误操作、抢麦、发热、耗电、ANR 或不可恢复错误。
6. 新管理站部署影响 `bb.chinacedar.top:2305` 现有专家服务。
7. 无试点客户/真实现场流程，却继续扩展多行业目录。

## 10. 调整后的开发顺序

1. **修复可信基础**：管理路由、任务完成状态、Android 事件接入、APK 密钥边界、测试缺口。
2. **锁定首发产品合同**：楼宇/HVAC 一条真实流程；轻量工单/资产模型；CMMS/EAM/MDM 边界和 API。
3. **身份与设备控制面**：组织、账号生命周期、角色/项目范围、OIDC、设备绑定/撤销、受管凭据和审计。
4. **项目/任务/证据闭环**：事件 outbox、媒体上传、失败恢复、结束摘要、项目记录和显式恢复。
5. **SkillRuntime + Knowledge**：版本、审核、分配、评估、服务端 ExecutionContext、引用、观测和回滚。
6. **项目记忆**：明确项目指令的来源、版本、撤销、隔离和人工提升知识流程。
7. **统一音频与双语音模式**：先协调器和互斥状态机，再接小叮当与声纹入口。
8. **声纹可选增强**：后端代理、同意/录入/删除/锁定/反重放和真实噪声/延迟验收；默认关闭直至过门槛。
9. **管理工作台补齐**：人员、声纹、知识、技能、审计、同步运营、指标和无障碍。
10. **连接器与市场硬化**：CMMS/EAM/MDM、SSO、可观测性、安全、备份恢复、负载/弱网/长稳和试点。
11. **GA 发布**：独立部署、正式签名、稳定包名、升级/回滚、运维手册、支持 SLA 和市场证据。

此顺序的原则是每一阶段都产生一条可运行、可验证、可撤销的垂直闭环；没有真实后端和验收证据时，不向正式 UI 暴露下一阶段功能。

## 11. 最终判断

V9 的价值不在“功能比竞品多”，而在于把眼镜、AI、技能、项目记忆、证据和专家协同做成一个比大型现场服务移动端更快、更确定、更可追溯的执行体验。这个方向具备继续投入的理由。

但当前代码只能视为 **V9 基础设施阶段**。在修复 P0、完成单垂直真实闭环、部署真实云端、通过 V9 Air3/安全/试点门槛前，不能对外声称账号、声纹、知识库、Skill、项目记忆或云端联动已经完成，也不能作为可直接进入市场的合格产品发布。
