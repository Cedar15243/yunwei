# V9 SRE 与安全放行门禁实施计划

日期：2026-08-06

## 成功标准

1. V9 网关 SQLite 数据可生成带哈希和完整性检查的备份，可在停止服务后原子恢复；损坏备份必须在改写生产数据前失败。
2. 网关保留轻量 `/health` 存活探针，并新增不访问外部 AI、ASR、声纹或 MVS 的 `/ready` 本地就绪探针，避免影响眼镜响应速度。
3. 部署资产包含定时备份、只读恢复演练、黑盒监控告警规则和明确的 RPO/RTO/值班处置合同。
4. 仓库安全规则扫描作为正式打包门禁；外部 DAST/渗透测试没有真实目标时保持 `pending`，不得伪造通过。
5. 正式交付包包含新的运行手册、可执行资产与机器可读审计报告，并继续标记市场 GA 受外部条件阻断。

## 范围边界

- 不修改 V8、现有稳定 APK、专家协同站点、Air3 HUD 视觉和固定模型合同。
- 不连接或改写生产 Supabase、MVS、服务器和账号。
- 不把本地恢复演练等同于生产恢复演练，不把仓库规则扫描等同于第三方渗透测试。

## 实施顺序

1. 先写备份恢复、就绪探针、部署资产和安全门禁的失败测试。
2. 实现最小运行时代码与部署资产，使小范围测试通过。
3. 接入 `package:v9-delivery` 和 `validate:v9-delivery`。
4. 运行网关、脚本、交付与相关全量验证，更新完成度矩阵和 `agent_memory`。

## 停止条件

- 需要生产凭据、线上目标、供应商审批或会影响现有专家站点时停止本地实现并记录外部阻断。
- 任一恢复测试可能覆盖工作树外真实数据时立即停止；所有自动化恢复仅使用临时目录。
