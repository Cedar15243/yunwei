# V9 Android WorkflowRuntime 实施计划

日期：2026-08-01

## 目标

在不改变现有首页、HUD、Camera2、语音、AI 对话和专家协同页面的前提下，实现眼镜端已签名工作流执行包的验证、原子缓存、确定性执行、证据门禁、离线恢复和同步上报。

## 成功标准

1. 摘要、签名、schema、最低版本、能力或分配元数据任一不一致时拒绝执行并保留上一份有效快照。
2. 已验证执行包原子落盘，进程终止或设备重启后恢复原工作流版本、当前节点、草稿、证据引用和待发事件。
3. 普通节点本地推进；照片、视频和表单先可靠保存，AI、专家和连接器离线时进入明确等待状态。
4. 必填证据、人工确认和高风险门禁不能被 AI 输出或客户端状态跳过。
5. 节点通过能力注册表复用现有 Camera2、语音、AI、专家和任务能力，不新增第二套页面系统。
6. Android 单元测试、构建、静态合同、Test Android Apps/ADB 和 Air3 实机验证全部通过后才允许进入发布候选。

## 实施顺序

1. `WorkflowPackageVerifier`：规范化摘要、Ed25519 公钥、严格执行包和兼容性验证。
2. `WorkflowPackageStore`：原子文件、上一有效快照、执行状态和损坏恢复。
3. `WorkflowStateMachine`：节点/转移、类型化条件、有界重复、终态和状态快照。
4. `WorkflowEvidenceGate`：字段、照片、视频、语音、人工确认、同步和在线门禁。
5. `WorkflowCapabilityRegistry`：映射现有原生能力和固定 HUD 模板。
6. `WorkflowSyncReporter`：分配状态、执行启动、步骤事件、幂等 outbox 和重启补发。
7. 在现有维修工单/现场应用入口接入，不抢占当前任务；完成端到端弱网和非回归验证。

## 停止条件

- 无法验证生产公钥来源；损坏包会覆盖有效缓存；状态机可跳过证据或确认；网络失败导致现场数据丢失；运行时影响 Camera2、音频、AI、专家协同、温升、耗电或 ANR。任一条件成立时停止接 UI，回到当前层修复。
