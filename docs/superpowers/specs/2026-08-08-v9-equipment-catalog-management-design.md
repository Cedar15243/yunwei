# V9 设备记忆目录受控维护设计

## 目标

让组织管理员在现有“人员与设备 -> 设备记忆”页面维护真实设备目录，并让变更通过现有服务端授权目录自动联动眼镜端。不得新增本地假数据、客户端直写 Supabase、物理删除历史设备或绕过项目权限。

## 范围

- 新建设备：设备编号、系统、品牌、型号、数量、状态、最近巡检时间、故障/维修次数、关键参数和至少一个关联项目。
- 编辑设备：修改同一组字段并原子替换项目关联。
- 不提供删除；退役使用 `decommissioned`，保留任务、项目和审计历史。
- 眼镜端不增加写能力，继续通过短期设备会话只读 `GET /device-sync/device-memory`。

## 权限与安全

- 仅 `super_admin`、`ops_admin` 可调用写接口。
- 每次写入必须提交显式确认字符串、3-240 字操作原因和 8-200 字幂等键。
- 编辑必须携带当前 `updatedAt`，数据库比较版本；过期版本返回 `409 equipment_version_conflict`，禁止静默覆盖。
- 项目 ID 必须全部属于当前组织；设备编号在组织内唯一。
- 数据库 RPC 使用事务一次完成设备写入、项目关联替换和不可变审计；函数只授权 `service_role` 执行。

## 接口

- `POST /management/equipment`
  - 确认：`CREATE_EQUIPMENT`
  - 成功：`201`，返回更新后的设备 DTO。
- `PUT /management/equipment/:equipmentId`
  - 确认：`UPDATE_EQUIPMENT`
  - 成功：`200`，返回更新后的设备 DTO。
- 重复幂等键返回第一次成功结果，不重复写入或重复审计。

## 管理 Web

- 设备记忆工具栏新增“登记设备”。
- 每行新增编辑图标；表单复用现有对话框样式，不改变页面主布局。
- 项目使用多选复选框；无项目时禁止提交。
- 提交前显示二次确认文案并要求操作原因；服务失败保留已填写内容。
- 成功后关闭对话框并刷新真实目录；冲突提示用户刷新后重试。

## 验收

- Edge：权限、确认、输入校验、组织隔离、幂等、唯一编号、版本冲突、原子项目替换和审计均有测试。
- Web：创建、编辑、项目多选、失败保留、成功刷新和无假数据均有测试。
- 回归：管理 Web 全量、Edge 定向与全量、Deno check、Supabase 验证、Android 设备记忆只读回归和发布门禁。
