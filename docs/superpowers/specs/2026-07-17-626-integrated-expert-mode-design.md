# 626 集成专家协同模式设计

## 1. 目标

在完整保留 626 版“叮当 AI 运维专家”聊天、拍照、语音、项目记录和既有诊断能力的前提下，将已验证的 TRTC 专家协同能力集成到同一应用体验中。

现有核心功能正式命名为“AI 智能运维指导”。本阶段只新增交付“远程专家协同”，其余运维能力预留稳定入口和代码接口，后续实现时不得再次改动主导航和媒体资源架构。

## 2. 版本与保护策略

- 原 626 源码快照、构建脚本、设备安装包和应用数据保持不变。
- 新建独立 Gradle 工程 `air3-dingdang-expert-integrated-app/`，从 626 已确认源码复制后独立演进。
- 真机开发阶段使用测试包：
  - 包名：`com.codex.air3nativecamera.dingdangexpert.follow.preview`
  - 版本：`627 / 6.2.7-expert-preview`
  - 应用名：`叮当AI运维专家·协同测试`
- 测试包与原 626、独立协同 801 并行安装，任何自动化脚本都必须验证三者未被覆盖。
- 全部回归通过后，才允许生成正式升级包：
  - 包名：`com.codex.air3nativecamera.dingdangexpert.follow`
  - 版本号至少为 `627`
  - 必须使用与 626 相同的签名证书，以保留原应用数据并执行覆盖升级。
- 未经用户明确确认，不安装正式升级包。

## 3. 用户入口

### 3.1 聊天页入口

眼镜首页第一阶段展示四个主入口：

1. `AI 智能指导`：现有 626 核心能力。
2. `专家协同`：本阶段可用，进入专家协同模式。
3. `设备巡检`：本阶段只保留入口和接口，不启动巡检流程。
4. `现场记录`：本阶段只保留入口和接口，不启动录像或证据采集。

`更多运维` 中预留：

- `设备档案`
- `运维工单`
- `运维知识库`
- `运维报告`
- `安全作业`
- `培训演练`

未实现入口被点击时只显示明确的“下一阶段启用”状态，不申请权限、不占用相机和麦克风、不写入伪记录。

### 3.2 语音入口

增加语音命令：

- `呼叫专家`、`打开专家协同`：进入专家协同模式并停留在待呼叫页面。
- 不自动发起呼叫，避免误触造成音视频连接和免费时长消耗。

后续预留但本阶段不启用：`开始录像`、`开始巡检`。

## 4. 应用模式

主页面模式由现有 `CHAT / CAMERA` 扩展为：

- `CHAT`：原 626 聊天、语音和项目记录。
- `CAMERA`：原 626 拍照和照片确认。
- `EXPERT`：专家呼叫、TRTC 音视频、实时标注和冻结画面。

全部预留功能暂不进入页面模式枚举，只通过 `FeatureEntry` 接口注册，等功能实现时再增加各自状态机。

## 5. 模块边界

### 5.1 626 宿主

复制后的 `MainActivity` 继续负责：

- 原聊天项目与 SharedPreferences 数据格式。
- 原聊天、拍照、语音命令和硬件键行为。
- 主模式切换和媒体资源所有权。
- 专家模式入口与退出后的状态恢复。

不得把 TRTC、WebSocket 或标注协议继续堆入原单文件。

### 5.2 专家协同模块

从独立 801 工程迁入并保持独立类：

- `ExpertCollabView`：专家模式 UI 和进入/退出命令。
- `CollabStateMachine`：待机、呼叫、连接、通话、重连、失败、结束。
- `CollabSocketClient`：WebSocket 信令和实时标注事件。
- `TrtcSessionController`：短期凭证、TRTC 进房、摄像头与麦克风发布。
- `AnnotationOverlayView`：实时标注叠加。
- `FreezeFrameView`：冻结图下载、显示和清理。

模块只通过 `ExpertModeHost` 接口请求进入、退出和状态提示，不直接修改聊天数据。

### 5.3 后续功能接口

定义统一的 `FeatureEntry`：

- `id()`：稳定功能标识。
- `title()`：菜单名称。
- `isAvailable()`：当前版本是否可用。
- `enter(Activity host)`：进入功能。
- `release()`：退出并释放资源。

本阶段注册以下稳定标识：

- `expert_collab`
- `equipment_inspection`
- `field_records`
- `asset_records`
- `work_orders`
- `knowledge_base`
- `operations_reports`
- `safe_operations`
- `training_drills`

只有 `expert_collab` 可用，其余入口不申请权限、不建立网络连接、不写入业务数据。

## 6. 媒体资源切换

### 6.1 进入专家模式

按固定顺序执行：

1. 保存当前项目、滚动位置、聊天草稿和当前页面。
2. 取消前台语音自动唤醒任务。
3. 停止正在进行的 ASR 录音并等待录音线程退出。
4. 关闭 Camera2 会话、设备、ImageReader 和相机线程。
5. 隐藏聊天与拍照层，显示专家协同层。
6. 连接协同 WebSocket；只有用户点击“呼叫远程专家”后才请求 TRTC。

### 6.2 退出专家模式

退出触发来源：

- 页面“退出专家模式”。
- 眼镜返回键、DPAD_LEFT 或 F10。
- 当前 Activity 被销毁。

按固定顺序执行：

1. 如有会话，向服务端发送挂断事件。
2. 离开 TRTC 房间并停止本地音视频。
3. 关闭 WebSocket、HTTP 请求和重连任务。
4. 清空标注与冻结图，销毁 TRTC 预览 View。
5. 恢复进入前的聊天项目、草稿、消息和滚动位置。
6. 重新启动 Camera2 资源。
7. 在录音权限可用且无 AI 流式回答时恢复原前台语音监听。

退出专家模式不能退出应用，也不能新建或清空聊天项目。

## 7. 硬件键行为

- `EXPERT` 模式下确认键：仅操作当前有焦点的呼叫/挂断按钮，不触发原语音录制。
- `EXPERT` 模式下返回键、DPAD_LEFT、F10：退出专家模式并回到聊天页。
- 相机键在 `EXPERT` 模式下不启动 Camera2，也不拍照，避免与 TRTC 抢占相机。
- 音量键继续交给系统音量行为，不改变原聊天模式逻辑。
- `CHAT` 和 `CAMERA` 下所有 626 按键行为保持原样。

## 8. 配置与安全

- APK 不包含 TRTC SDK 密钥，只包含协同服务 URL。
- UserSig 继续由服务端短期签发。
- 测试包通过 Gradle 属性注入局域网服务 URL，不写死开发电脑 IP 到源码。
- 626 原有后端密钥继续由现有 ignored 本地文件或环境变量注入，不进入 Git。
- 构建和日志不得输出完整 UserSig、后端密钥或 TRTC 密钥。

## 9. 错误处理

- 进入专家模式前资源释放失败：停留聊天页并显示错误，不进入半初始化状态。
- 协同服务离线：专家页显示可重试状态，返回键仍可退出。
- TRTC 进房失败：释放 TRTC 资源但保留专家模式，允许重新呼叫或退出。
- 退出清理出现迟到回调：通过 generation 标识忽略，不重新进入通话状态。
- 恢复 Camera2 或语音监听失败：回到聊天页并显示诊断状态，聊天记录仍可访问。

## 10. 验证标准

### 10.1 自动化

- 原 626 HUD、构建版本、语音命令和项目记录验证继续通过。
- 专家状态机、UserSig、WebSocket、标注映射和退出迟到回调测试通过。
- 新增模式切换测试：`CHAT -> EXPERT -> CHAT` 和 `CAMERA -> CHAT -> EXPERT -> CHAT`。
- 敏感信息扫描和原 626 哈希保护通过。

### 10.2 真机

使用独立 627 测试包完成：

1. 在 627 预览包中创建测试聊天项目，确认进入专家模式前后的消息和标题保持不变；原 626 数据继承只在正式同包升级评审阶段验证。
2. 从菜单进入专家模式，呼叫并与网页专家通话。
3. 验证实时视频、语音、标注、冻结和截图。
4. 通话中用返回键退出，确认网页收到挂断。
5. 确认回到原聊天项目，草稿、历史记录和语音监听恢复。
6. 再次进入并退出，至少连续执行三次。
7. 回归拍照、使用照片、语音提问、新建项目、切换历史记录和网站诊断。
8. 确认原 626、801 和 627 测试包同时存在且版本未变化。

完成以上验证后，再单独评审是否用正式 627 升级原 626。

## 11. 本阶段不做

- 不实现本地或云端录像文件及现场证据采集。
- 不实现录像回放、上传、存储配额和权限管理。
- 不实现设备巡检模板、检查项、扫码、结果提交和报告。
- 不安装或覆盖正式 626 包。
- 不新增录制、云存储或其他收费服务。
