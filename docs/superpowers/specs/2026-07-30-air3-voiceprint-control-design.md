# Air3 声纹控制设计

## 目标

在不再要求用户说“小叮当”的前提下，使用 Air3 实体按键建立一次受控语音输入，并用讯飞声纹识别（新版）的 `1:1` 验证确认操作者身份。通过验证的语音才可执行内置命令或发送给当前 AI 运维任务。

本功能以新候选 APK 交付，不能覆盖已安装的 `v8.0.48` 稳定包。

## 已确认约束

- 用户确认使用实体按键，不采用全天候云端监听。
- 当前讯飞账号已购买 `¥0` 声纹识别（新版）免费包，额度为 100,000 次，到期时间为 2026-10-28 17:15。
- 现有 ASR、AI 对话、任务状态机、拍照、专家协同保持原实现；声纹只作为语音输入的授权门。
- 声纹是生物识别数据。原始录音、讯飞密钥和声纹模板均不得写入 APK、任务记录或调试日志。

## 交互模型

### 三种模式

1. `PASSIVE`：默认状态。App 不采集麦克风、不上传、不转写；现场讲解和旁人谈话不会产生记录或操作。
2. `PUSH_TO_TALK`：用户长按实体键后开始采集本轮语音，HUD 底部显示“请直接说操作”；松开实体键即结束本轮录音。
3. `VERIFYING`：录音结束后先执行讯飞声纹 `1:1` 验证。验证通过才进入命令路由或 AI 对话；结束后始终回到 `PASSIVE`。

不实现“按一次后无限监听”“后台声纹监控”“自动从讲解中抽取命令”。

### 实体键策略

当前 `MainActivity` 已记录并处理 Air3 硬件事件。现有发送键集合为 `KEYCODE_DPAD_RIGHT`、`KEYCODE_MENU`、`KEYCODE_F12`；短按在聊天页用于发送文本、结束录音或切换任务栏。

- 新版本使用该集合中的实际 Air3 可稳定触发键作为语音键。
- 长按达到 `500ms`：进入 `PUSH_TO_TALK`，并消费本次按键，避免触发短按动作。
- 松开：结束录音并开始验证。
- 未达到 `500ms`：完整保留现有短按行为。
- 相机键、返回键、确认键、翻页键和音量键绝不承担声纹入口。
- 首次 Air3 验收从现有 `dispatchKeyEvent` 日志确认可见的 `keyCode`、`scanCode` 和按住/松开事件；若默认候选没有可靠长按事件，则仅切换候选键，不改变其他流程。

### 验证后的行为

- 通过声纹且转写匹配内置命令：调用现有 `VoiceCommandRouter`。例如“返回首页”“下一页”“现场拍照”“呼叫专家”。
- 通过声纹但不是内置命令：保留在当前任务页，将该文本作为本轮用户输入发送给既有 AI 对话。
- 声纹未通过：显示“未识别为授权操作者”，不路由命令、不保存转写、不发送 AI。
- 声纹服务不可用、网络超时或录音为空：显示可恢复提示，保持当前页面和任务；用户可重新长按语音键或使用现有屏幕/按键操作。
- 专家通话、录像和相机独占麦克风时：语音键显示不可用提示，不抢占音频资源。
- 呼叫专家、结束任务、保存维修记录、重新开始任务：声纹通过后仍需现有确认动作；翻页、返回首页、拍照不增加确认。

## 语音数据与安全边界

1. 用户主动长按后才创建内存 PCM 缓冲；最长录音 12 秒，松开即停止。
2. PCM 先发送到讯飞声纹服务进行 `1:1` 验证。未通过时立即清除内存缓冲，不向现有云端 ASR、AI 后端或任务历史发送内容。
3. 通过后，才将同一段音频交给现有 ASR；ASR 最终文本才可进入任务记录和 AI。
4. 命令延迟优先级：本地 ASR 可作为短命令的临时识别候选，但只有声纹通过后才能实际执行；开放式描述仍在声纹通过后调用现有 ASR。
5. 讯飞 `APPID`、`APIKey`、`APISecret` 仅配置在服务端密钥环境中。Android 只持有登录态或一次性调用令牌，不能直连携带秘密。
6. 服务端只保留加密的讯飞声纹库标识、用户授权版本、操作者与设备绑定信息、验证结果和时间；默认不保留原始音频。

## 声纹生命周期

- 首次注册只能由已登录的操作者在“声纹控制”设置中手动触发。
- UI 展示用途、使用的云服务、数据保留规则和删除入口；用户明确同意后，录制 3 段自然中文语音，每段 6-10 秒。
- 服务端创建或更新该操作者的声纹库，并进行一次即时 `1:1` 验证；通过后才标记该设备可使用声纹控制。
- 设置中提供“重新录入”和“删除我的声纹”。删除需二次确认，并同时删除服务端绑定记录与讯飞侧模板/特征库。
- 验证连续失败 3 次时，暂停声纹控制 60 秒，但始终保留屏幕和原有实体按键操作。

## 组件边界

- `VoiceControlStateMachine`：纯 Java 状态机，决定长按、松开、超时、验证完成和音频占用时可否进入下一状态。
- `HardwareVoiceKeyPolicy`：纯 Java 长按判定和短按抑制策略；不包含 Android UI。
- `VoiceIdentityService`：Android 接口，处理注册、验证和删除；实现只调用项目后端代理。
- `VoiceprintGateway`：`supabase/functions/ops-glasses` 的鉴权代理，负责讯飞 WebAPI 请求签名、密钥托管、模板库操作、验证结果归一化和审计。
- `MainActivity`：只负责实体键事件、HUD 状态、录音生命周期以及将授权后的文本交给现有 `VoiceCommandRouter` / ASR / AI 任务流。

## 不采用的方案

- 全天候 ASR 加声纹：会记录无关讲解，产生隐私、耗电、发热和误触发风险。
- 仅用说话人分离：它不能证明说话人是否为已登记操作者。
- 客户端直接调用讯飞：会泄露密钥，无法进行操作者授权、模板删除和审计。
- 用 LLM 判断是否为本人或是否为命令：结果不可确定，不能用于页面控制。

## 验收标准

### 自动化

- 长按语音键进入录音，短按仍保留原聊天动作。
- 相机、返回、确认、翻页、音量键的既有行为不回归。
- 声纹通过且命令为“下一页”时，只影响当前页面的分页，不跳到监听页或首页。
- 声纹通过且是普通问题时，文本进入当前任务对话，不触发内置命令。
- 声纹失败、超时、空音频、专家通话或录像占麦时，均不执行命令且不丢失当前任务。
- 返回首页或新建任务后，上一个任务的录音和验证结果不可复用。

### Air3 实机

- 目标实体键可稳定识别 `DOWN`、长按、`UP`；短按无回归。
- 本人连续 20 次短命令中，至少 18 次按预期进入验证和路由链路；旁人 20 次不执行任何命令。
- 现场讲解 10 分钟未按语音键时，无 ASR 请求、无 AI 新消息、无任务记录。
- 长按到 HUD 显示录音反馈小于 150ms；录音结束到命令执行或明确失败反馈小于 3 秒，网络差时给出可恢复提示。
- 专家通话、拍照、录像、返回首页、连续任务和 20 分钟待机均无 crash、ANR 或麦克风占用残留。

## 发布边界

- 新包使用新的 `applicationId`、递增 `versionCode` 和清晰的声纹候选版标签，与 `v8.0.48` 并存。
- 先完成 JVM 单元测试、Android 构建、后端类型检查和受控设备测试；通过后才安装候选包，不自动替换稳定包。
