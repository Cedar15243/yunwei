# 叮当专家协同演示版设计

## 1. 目标

在 10 个自然日内交付一套可真机演示的远程专家协同系统：Air3 眼镜一键广播呼叫在线专家，第一位接听者成为主专家；主专家通过浏览器查看眼镜第一视角、双向语音并实时标注，其他专家可被邀请旁听和语音加入。

本项目以 626 版 `叮当AI运维专家` 的眼镜交互经验为基线，但不得修改、覆盖或重新解释 626 的包、源码快照、构建脚本、安装脚本和设备数据。

## 2. 固定范围

### 2.1 必须完成

- 新眼镜包与 626 并行安装。
- 眼镜端一个主按钮广播呼叫所有在线专家。
- 第一位接听者成为主专家，拥有标注和会话控制权。
- 主专家可以邀请其他在线专家旁听并语音加入。
- 旁听专家默认不能标注，避免多人同时修改画布。
- 眼镜端向 TRTC 房间发布第一视角视频和麦克风音频。
- 专家浏览器订阅眼镜视频，发布专家麦克风音频。
- 眼镜播放所有已加入专家的语音。
- 主专家支持画笔、箭头、圆圈、撤销和清空。
- 标注使用 `0..1` 归一化坐标，实时同步到眼镜透明覆盖层。
- 主专家支持冻结当前视频帧，在双方相同静态画面上继续标注，再恢复实时画面。
- 支持保存一张带标注截图作为演示记录。
- 显示在线、呼叫中、已接听、旁听中、断线和已结束状态。
- TRTC 后付费保持关闭；免费包用完或过期后允许服务自动停服。

### 2.2 本期不做

- 专家账号密码、企业单点登录和复杂权限后台。
- 专家排班、技能智能匹配、自动转接策略和离线消息。
- 多名专家同时标注、画笔抢占和复杂协同冲突合并。
- 云端录像、实时翻译、AI 智能语音和付费增值功能。
- 完整工单系统、历史回放、统计报表和客户级审计后台。
- 后台热词唤醒、接管 INMO 系统保留按键或系统级常驻能力。
- 商用级多区域部署、容灾、SLA 和大规模并发。

## 4. 方案比较

### 4.1 方案 A：TRTC 无 UI 自由集成 + 自有 WebSocket 协同层（采用）

TRTC 只承担摄像头、麦克风、弱网、回声消除和多人房间；呼叫状态、专家在线列表、主专家抢接、邀请旁听、冻结画面和标注事件由自有服务控制。

优点：完全匹配眼镜 UI 和 QQ 式专家工作台，标注协议可控，626 不受影响。缺点：需要分别开发 Android、Web 和演示服务。

### 4.2 方案 B：TUIRoomKit 会议组件 + 自定义标注覆盖层

优点：入会、成员列表和基础会议控件开发更快。缺点：眼镜端 UI 重、定制受限，和现有横屏眼镜操作不一致，标注与冻结画面仍需单独开发。

### 4.3 方案 C：自建 WebRTC/SFU + 自有信令

优点：完全自主。缺点：10 天内无法可靠完成 TURN、SFU、弱网、音频处理和设备兼容验证，不适合作为本期路线。

## 6. 组件设计

### 6.1 眼镜端

眼镜首页仅保留现场人员必需的信息：产品名、专家连接状态、当前主专家、一个呼叫/挂断主按钮和网络错误提示。进入协同后显示 TRTC 本地相机预览，标注层始终位于预览之上。

状态机：

```text
IDLE -> CALLING -> CONNECTING -> IN_CALL -> ENDED
          |            |           |
          v            v           v
        FAILED <---- RECONNECTING --+
```

眼镜端在 `IN_CALL` 状态发布摄像头和麦克风。收到 `freeze.created` 后显示专家端上传的冻结帧，收到 `freeze.cleared` 后恢复本地实时预览。

### 6.2 专家网页

固定三栏布局：

- 左栏：眼镜现场与在线专家列表，显示在线、忙碌、离线。
- 中栏：眼镜第一视角视频、实时标注、冻结、截图和会议控制。
- 右栏：当前成员、主专家角色、旁听状态、截图记录和连接质量。

主专家可标注、邀请旁听、冻结、截图和结束会话。旁听专家可以观看、收听和说话，但标注工具禁用。

### 6.3 演示服务

服务使用 Node.js、HTTP 和 WebSocket。演示阶段会话和在线状态保存在内存中，截图写入忽略的运行目录。服务职责：

- 根据服务端密钥生成短期 TRTC `UserSig`。
- 注册专家在线状态和眼镜在线状态。
- 广播眼镜呼叫。
- 原子确定第一位接听者为主专家。
- 管理旁听邀请和成员角色。
- 转发标注、冻结和截图事件。
- 会话结束后清理房间内存。

## 7. 实时协议

所有消息包含：

```json
{
  "type": "call.accepted",
  "sessionId": "session_01",
  "senderId": "expert_wang",
  "seq": 18,
  "sentAt": 1784253600000,
  "payload": {}
}
```

核心事件：

- `presence.registered`
- `presence.changed`
- `call.requested`
- `call.accepted`
- `call.busy`
- `call.ended`
- `participant.invited`
- `participant.joined`
- `participant.left`
- `annotation.begin`
- `annotation.append`
- `annotation.end`
- `annotation.undo`
- `annotation.clear`
- `freeze.created`
- `freeze.cleared`
- `snapshot.saved`
- `error`

标注点格式：

```json
{
  "objectId": "stroke_01",
  "tool": "arrow",
  "color": "#ff5f67",
  "width": 0.006,
  "points": [{ "x": 0.42, "y": 0.31 }, { "x": 0.58, "y": 0.49 }]
}
```

`x`、`y` 和 `width` 均相对视频有效内容区域归一化。Web 与 Android 必须使用相同的 `contain/cover` 映射规则，不能直接传屏幕像素。

## 8. 呼叫流程

1. 眼镜连接演示服务并注册设备身份。
2. 现场人员点击“呼叫专家”。
3. 服务向所有在线且非忙碌专家广播 `call.requested`。
4. 第一位点击接听的专家通过服务端原子检查成为主专家。
5. 服务为眼镜和主专家返回同一个 TRTC 房间号及短期 `UserSig`。
6. 双方进入 TRTC 房间，眼镜发布视频和音频，专家发布音频。
7. 主专家可以邀请其他在线专家；受邀专家以 `observer` 角色进入同一房间。
8. 主专家结束后，服务广播 `call.ended`，所有端退出 TRTC 房间并清理标注状态。

## 9. 冻结与标注流程

实时模式下，专家 Canvas 与眼镜 `AnnotationOverlayView` 分别维护同一组对象。高频轨迹以每秒最多 20 批发送，减少网络和眼镜绘制压力。

冻结时，专家浏览器从当前远端视频帧生成压缩 JPEG，上传到演示服务并发送 `freeze.created`。眼镜下载同一帧替换本地预览，确保双方标注背景一致。恢复时发送 `freeze.cleared`，双方清空冻结帧并回到实时视频。

## 10. 错误处理

- TRTC 入会失败：显示中文错误和“重试”，不暴露 SDK 密钥或完整内部错误。
- WebSocket 断开：指数退避重连；通话中标注暂停，但 TRTC 音视频继续。
- 主专家重复抢接：服务只接受第一个，其他专家收到 `call.busy`。
- 主专家掉线：10 秒内重连保留角色，超时后会话结束；演示版不自动选举新主专家。
- 旁听专家掉线：从成员列表移除，不结束会话。
- 冻结帧上传失败：保持实时视频，提示“冻结失败，请重试”。
- 免费 TRTC 服务停服：明确显示“免费音视频额度不可用”，不尝试开启后付费。

## 11. 安全规则

- TRTC SDK 密钥仅由演示服务读取。
- Web 与 Android 只接收短期 `UserSig`。
- 日志禁止输出 SDK 密钥、完整 `UserSig` 和会话访问令牌。
- 截图目录默认被 Git 忽略。
- 演示服务只监听开发环境指定地址；外网部署前必须增加 HTTPS、WSS 和身份认证。
- 不启用腾讯云后付费、云端录制、实时翻译或 AI 增值能力。

## 12. 验证与成功标准

### 12.1 自动验证

- Web 单元测试覆盖主专家抢接、角色权限和归一化坐标转换。
- Server 单元测试覆盖第一人接听、旁听邀请、断线和会话清理。
- Android 单元测试或纯 Java 测试覆盖状态机、协议解析和坐标映射。
- Web 构建、Server 测试、Android 构建和 `git diff --check` 全部通过。

### 12.2 真机验证

- 新包与 626 同时安装，626 包名、版本和数据保持不变。
- 眼镜点击一次后，两个专家浏览器都出现来电。
- 第一位接听者成为主专家，第二位接听被拒绝或转为等待邀请。
- 主专家在浏览器看到 Air3 第一视角并完成双向语音。
- 主专家绘制箭头和圆圈，眼镜在 500ms 目标延迟内显示同位置标注。
- 邀请第二位专家后，第二位专家可旁听和说话，但不能标注。
- 冻结后双方显示同一帧，恢复后回到实时画面。
- 保存一张带标注截图。
- 连续通话 20 分钟无崩溃，记录温度、PSS、丢帧和关键日志。
- TRTC 控制台保持后付费未开通。

## 13. 10 天开发节奏

- 第 1 天：独立工程、协议、演示服务骨架、TRTC 凭证接口。
- 第 2 天：Android 与 Web 分别跑通 TRTC 入会和基础音视频。
- 第 3 天：眼镜发布第一视角、专家网页订阅、双向语音。
- 第 4 天：在线专家列表、广播呼叫和第一人抢接。
- 第 5 天：主专家实时画笔与眼镜标注层。
- 第 6 天：箭头、圆圈、撤销、清空和角色权限。
- 第 7 天：旁听专家邀请与多人语音。
- 第 8 天：冻结帧、截图和断线重连。
- 第 9 天：Air3 真机连续联调、性能和弱网修复。
- 第 10 天：完整演示回归、APK 构建、网页启动脚本和演示预案。

## 14. 停止条件与降级方案

第 2 天结束前必须证明 Air3 能通过 TRTC 稳定发布摄像头和麦克风，浏览器可订阅。如果 TRTC SDK 与 Air3 编码器或相机不兼容，立即降级为眼镜定时 JPEG/低帧率画面上传 + TRTC 双向语音 + 相同标注协议，保证第 10 天仍有完整专家协同演示闭环。
