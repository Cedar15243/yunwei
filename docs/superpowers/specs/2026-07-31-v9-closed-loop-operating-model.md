# V9 现场作业与云端管理闭环运行模型

## 1. 产品承诺与真实性规则

V9 的目标不是增加展示页，而是让眼镜、AI、项目记录、云端管理、知识库和技能版本在同一条真实业务链上工作。任何正式 UI 入口都必须具备真实的数据来源、鉴权、状态写入、失败状态、恢复动作和测试证据；没有这些能力的功能不显示为可用功能。

- 正式包、正式网页和正式云端环境不使用 mock、fixture、演示成功状态或本地硬编码结果替代真实执行。
- 测试数据只能存在于单元测试、隔离测试项目或明确标示的开发构建中，不能进入 V9 正式部署数据、界面和决策链路。
- 后端/授权/网络不可用时，明确显示当前不可执行的阶段和可恢复动作，保留项目、证据和待发队列；不得伪造技能已生效、媒体已上传、任务已完成或知识已更新。
- 现有专家 Web、眼镜首页和已确认 HUD 视觉保持冻结。V9 的新入口放在现有三道杠菜单/能力中心的既有样式中，不新增第二套视觉系统或改变首页布局。

## 2. 真实闭环

`账号与设备授权 -> 新建/恢复项目 -> 选择或打开已授权技能 -> 采集语音/图像/视频 -> 项目记忆与任务事实 -> 服务端 AI 编排 -> 维修/巡检步骤 -> 人工确认或异常/专家 -> 任务结束摘要 -> 项目记录 -> 人工审核知识沉淀 -> 已发布技能/知识受控下发`

每个箭头都要求：组织/项目/任务/用户/设备范围，版本、时间、操作者、幂等键、审计事件，以及离线恢复语义。

## 3. 技能不是目录，而是 AI 执行上下文

### 3.1 激活语义

- 只有云端已发布且分配给当前组织、人员和设备的技能才能显示为可启用。
- 用户在眼镜端打开并启用一个已授权技能后，该技能立即成为当前项目的 `active_skill_snapshot`。后续 AI 对话必须经过后端的技能解析器，不能仅改变前端标题或本地目录状态。
- HUD 显示当前技能名称、版本和授权状态；关闭技能后后续对话回到通用 AI，但已发生的任务仍保留原技能快照。
- 未授权、未同步、已撤销、版本校验失败或后端不可用时不能进入伪激活状态；界面给出准确原因和重试/返回动作。

### 3.2 技能包内容与版本

每个技能包使用结构化、版本化配置，而不是下发任意代码：适用设备/系统、触发与排除条件、口语变体、现场步骤、阈值、SOP、补拍要求、风险、专家升级条件、允许的操作、知识库检索范围、参考图、输出边界、发布说明和授权策略。

草稿 -> 模拟验证 -> 审核 -> 发布 -> 分配 -> 使用 -> 观测 -> 回滚 是完整生命周期。发布产生不可变版本；回滚是重新分配旧版本，不修改历史任务。

### 3.3 后端 AI 编排

每次 AI 调用由服务端构建不可伪造的 `ExecutionContext`：

1. 平台安全策略与权限边界。
2. 当前任务固定的技能版本及其约束。
3. 当前项目的已确认事实、步骤状态、明确项目指令和摘要。
4. 已发布且有权限的知识库检索结果及来源引用。
5. 最近对话、当前用户消息、转写和本轮证据。

用户文本、图片、视频、知识文档均视为不可信内容，不能修改平台策略、技能权限、设备权限或记忆写入规则。模型仅能给出建议、所需证据和允许动作；关闭任务、删除资料、外部写入、呼叫专家等由明确的应用确认流程执行。

## 4. 三层记忆与“越用越聪明”

### 4.1 当前任务工作记忆

任务内保存临时对话、当前证据、已确认/排除事实、风险、步骤、当前技能快照和当前知识引用。任务结束后形成不可变摘要，不自动污染其他项目。

### 4.2 项目持久记忆

每个项目有独立的项目记录文件/云端记录：设备与型号、任务摘要、证据索引、对话、事实、风险、步骤、结果、当前/历史技能版本、知识引用、专家记录和项目指令。

当现场人员明确表达“以后在本项目遇到 X 要按 Y 做”一类操作规则时，应用创建带原始引用的 `project_instruction`：内容、条件、来源消息/操作者、创建时间、状态和版本。它立刻显示“已写入项目记忆”，后续同项目的 AI 调用检索匹配的有效指令。用户可在项目记忆中查看、编辑、停用、删除或恢复历史版本。

AI 的推测、非明确口语、外部知识文本和图片中的指令不能自动写入项目记忆。项目指令只在当前项目生效，除非管理员审核后将其提升为组织知识或技能规则。

### 4.3 组织知识与技能学习

人工确认完成的案例可生成知识草稿。审核后才成为已发布知识，供适用技能检索引用。系统以“可追溯的案例、确认事实、显式指令和已发布规则”变聪明，而不是把模型猜测或旧项目结论直接带到新项目。

## 5. 任务结束、项目记录和恢复

- AI 给出结束建议不等于关闭任务。现场人员确认完成后，显示结束摘要：已完成步骤、未解决风险、证据、技能/知识版本、下一步建议和同步状态。
- 结束页提供：继续当前任务、确认结束并回首页、查看/补充项目记忆、呼叫专家。确认结束才写入 `task_completed`/`task_closed` 事件和项目摘要。
- 项目记忆入口在既有菜单中，提供项目列表、状态、更新时间、设备、摘要、同步状态、技能版本和最近风险；支持搜索、筛选、查看时间线、导出授权记录、显式“继续该项目”。
- 继续项目先显示恢复摘要和正在使用的旧技能快照；用户确认后恢复项目/任务。若用户选择重新分析，才对比新发布技能或知识版本，绝不静默替换。
- 新建项目、关闭任务回首页后，下次输入必须创建新任务。返回首页只是离开当前页面，项目仍可恢复。

## 6. 设置与运维入口

在既有菜单增加“设置”和“项目记忆”入口，复用当前 HUD 风格。

- 设置：账号与设备绑定状态、声纹授权/录入/重录/删除、语音模式、相机/麦克风权限、同步与网络、离线存储、技能/知识缓存版本、隐私与数据保留说明、诊断与应用版本。
- 设置不显示密钥、设备明文 token、声纹模板或原始音频；不提供绕过权限的开关。
- 项目记忆：当前项目摘要与指令、历史项目列表、恢复/新建/关闭、同步状态和已授权导出。
- 账号、角色、设备凭据、项目授权、声纹撤销、知识发布和技能发布在云端管理后台执行并审计；眼镜只展示本人可操作的状态和动作。

## 7. 模块化云端架构

模块间使用版本化接口和领域事件，不通过页面或模型文本直接耦合：

- `IdentityAccess`: 账号、组织、角色、项目范围、会话、审计。
- `DeviceControl`: 设备绑定、MDM 策略、凭据、清单、同步健康。
- `VoiceIdentity`: 同意、模板引用、录入、验证、锁定、删除、供应商代理。
- `ProjectRecord`: 项目、任务、对话、事实、项目指令、摘要、恢复快照。
- `Evidence`: 媒体元数据、短时授权、分片上传、校验、重试、保留策略。
- `SkillRuntime`: 草稿/审核/发布/分配、清单、解析器、执行快照、观测和回滚。
- `Knowledge`: 分类、文档、案例、审核、版本、检索、来源引用和提升流程。
- `AIOrchestrator`: 服务端 `ExecutionContext`、模型调用、输出校验、引用和可恢复错误。
- `AuditCompliance`: 不可变审计、组织 RLS、导出、保留和删除策略。

每个模块可独立开发、测试、部署和回滚；跨模块动作使用幂等 outbox/event 队列。眼镜本地队列和云端事件的重复投递不得产生重复任务、媒体或记忆项。

## 8. 稳定性与安全门槛

- 麦克风、相机、录像、专家通话的资源所有权是显式状态机；后台同步/AI/媒体 I/O 不在 UI 线程执行。
- 网络错误显示阶段（身份、技能清单、上传、AI、声纹、同步）和恢复操作；照片、项目和本地队列不得丢失。
- 技能、知识、项目记忆、媒体和任务均使用组织/项目/任务/角色校验；媒体采用短时签名 URL；服务端从令牌推导身份而不信任客户端身份字段。
- 声纹不是网页主身份认证或唯一高风险授权因素；它是已登录、已绑定设备上下文中的操作门，关键动作仍要求明确确认。
- 需要提供重放攻击/旁人误识、权限越权、提示注入、离线恢复、重复事件、版本回滚和资源抢占的自动化与 Air3 实机证据。

## 9. V9 发布门槛

V9 正式发布前必须完成：真实云端迁移/Edge Function/管理 Web 独立部署；真实账号和设备绑定；声纹供应商授权与后端密钥配置；已发布技能真实影响 AI 对话的端到端验证；项目记忆写入/恢复验证；真实媒体上传/恢复验证；独立 APK Air3 回归、性能和日志证据；专家站点无侵入健康回归；发布清单、回滚步骤、校验和和审计材料。

## 10. 速度和硬件体验原则

- 技能清单和授权在安全前台同步时预取为验证过的本地快照；打开技能不额外等待网络。AI 调用保持一次眼镜到后端请求，服务端在同一次请求中解析技能、项目记忆和知识，禁止客户端串行追加请求。
- 声纹模式只在显式双击开启后使用一条采集链；声纹关闭和小叮当模式不运行声纹网络/CPU工作。相机、录像和专家协同具有更高音频优先级。
- “不影响速度”以实测性能门槛交付，而非文字承诺：技能启用后 AI 首 token 的 p95 劣化不得超过 150ms；双击状态反馈 p95 小于 150ms；声纹分段结束到执行/明确失败的在线 p95 小于 3 秒。任何超限、发热、耗电、掉帧、ANR 或音频占用残留均阻断发布。
