# 叮当 AI 运维眼镜 v8.0.49 专家协同 SDK 修复版

## 版本信息

- Git 版本：`8.0.49-expert-sdk`
- 基线：`v8.0.48`
- 建议 Android versionCode：`849`
- 建议 Android versionName：`8.0.49-expert-sdk`
- 原 `v8.0.48` 稳定标签和稳定 APK 不修改、不覆盖

## 本次修改

- 服务端 TRTC 凭证接口同时兼容 `userId` 和 `expertId`，并拒绝两个身份不一致的请求。
- 服务端凭证响应补充 `expertId`、`expertName` 和 `roomId`，其中 `roomId` 使用请求的 `sessionId`。
- 眼镜端只有在收到服务端 `presence.registered` 后才通知上层“信令已连接”，避免注册尚未确认就发起后续请求。
- 眼镜端在接听后延迟启动 TRTC 和相机，等待上一段 Camera2 资源释放，降低接听瞬间的资源竞争。
- 眼镜端 TRTC 本地预览和本地音频增加一次性启动保护，避免重复初始化。
- 退出通话时释放当前房间媒体资源，但不销毁进程级 TRTC 单例，避免延迟 Native 回调触发异常退出。
- 保持视频编码参数不降低：`1920x1080`、横屏、清晰度优先。
- 保持现有远程专家信令、视频双向通话和专家绘画功能协议不变。

## 对接注意事项

- 凭证接口请求应包含 `sessionId` 和 `expertId`，例如：

  ```json
  {
    "sessionId": "session-xxx",
    "expertId": "expert-wang",
    "expertName": "王工"
  }
  ```

- 字符串房间号必须传给 TRTC 的 `strRoomId`，不能传给数字型 `roomId`。
- 生产和预生产网关地址由构建参数注入，不在源码中写入密钥。
- `SDK_DEMO_CLIENT_SECRET`、TRTC 密钥、`userSig` 和 SSH 私钥不得提交到 Git。
