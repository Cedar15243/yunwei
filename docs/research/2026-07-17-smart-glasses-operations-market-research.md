# 智能眼镜设备运维功能市场调研

调研日期：2026-07-17

## 1. 调研范围

本次不评估市场规模和厂商营收，只研究工业智能眼镜、远程专家和现场服务产品正在销售或公开展示的功能，用于规划 626 集成版的产品路线。

重点样本：

- TeamViewer Frontline
- RealWear 工业智能眼镜方案
- 亮风台 HiAR / HiLeia
- Microsoft Dynamics 365 Remote Assist / Field Service

## 2. 市场共同能力

### 2.1 远程专家协作

成熟产品普遍包含：

- 第一视角实时音视频。
- 专家截图、冻结和画面标注。
- 多人会话、专家转接或旁听。
- 文件、图片、说明书和图纸共享。
- 通话过程和附件关联到工单或设备。

当前叮当专家协同已覆盖音视频、画面标注、冻结、截图和旁听，下一步差距主要是文件共享、会话记录与工单关联。

### 2.2 数字化巡检

市场上的巡检不是单独拍照，而是标准化任务：

- 扫码、设备编号或人工搜索确认设备。
- 按步骤显示检查项、标准值和安全提示。
- 每一步记录正常、异常、不适用。
- 采集照片、短视频、语音、测量值和设备状态。
- 异常时直接创建事件并携带设备、步骤和证据呼叫专家。
- 完成后生成可查询的巡检报告和设备历史。

亮风台将设备说明书、标准工作规程、远程协作、实时数据和记录管理放在同一巡点检方案中；TeamViewer Frontline Inspect 同样强调维护步骤、清单、说明和现场记录。

### 2.3 作业指导与知识

- 分步骤操作指导。
- 设备说明书、图纸、维修视频和历史故障查询。
- 专家经验沉淀为标准作业流程。
- 培训模式和现场模式复用同一套内容。
- 后续可加入 AI，根据设备与当前步骤回答问题。

### 2.4 证据与审计

- 自动记录任务开始、结束、人员、设备和位置。
- 保存照片、短视频、语音备注、专家截图和标注。
- 每条证据关联巡检步骤、异常和处理结论。
- 支持报告导出、复核、追溯和知识沉淀。

“录像”应属于证据中心，而不是孤立录像按钮。否则会产生无法检索的大文件，也无法证明录像对应哪台设备、哪次任务和哪个异常。

### 2.5 设备资产与工单

- 设备台账、位置、型号、厂家和负责人。
- 维修历史、巡检历史、故障代码和备件记录。
- 工单派发、接单、开始、暂停、转派和完成。
- 异常升级为维修工单或专家协同会话。
- 与 EAM、CMMS、MES、ERP 或 Field Service 系统集成。

Microsoft 官方文档明确把 Remote Assist 与 Field Service 的排班、工单、客户资产以及通话附件关联；这说明远程视频本身不是完整产品。

## 3. 推荐产品结构

### 3.1 眼镜端

主入口建议保持五项：

1. `智能问答`：现有 626 聊天、拍照、语音和诊断。
2. `专家协同`：当前优先集成的实时远程协作。
3. `设备巡检`：任务、检查项、读数和异常。
4. `记录中心`：照片、短视频、专家截图、标注和报告。
5. `设备资料`：说明书、图纸、历史维修和故障知识。

安全作业与培训后续可作为巡检任务类型，不需要立即增加更多首页入口。

### 3.2 管理网页

网页端后续应从“专家会议页面”扩展为运维工作台：

- 待处理呼叫和在线专家。
- 今日巡检任务、逾期任务和异常任务。
- 设备资产与历史记录。
- 证据查看、报告复核和导出。
- 巡检模板与标准作业步骤配置。
- 用户、角色、专家组和权限。

## 4. 开发优先级

### P0：当前演示必须完成

- 626 完整功能与专家协同进入、退出集成。
- 会话基础记录：开始时间、结束时间、现场设备、主专家、旁听专家、截图和标注数量。
- 专家协同异常后可正常返回原聊天项目。

### P1：最有商业价值的下一版本

- 设备台账最小版：编号、名称、型号、位置、照片。
- 二维码识别或手工搜索设备。
- 巡检任务与步骤清单。
- 正常、异常、不适用和数值录入。
- 照片、短视频和语音备注作为步骤证据。
- 异常一键呼叫专家，并自动携带设备与检查步骤。
- 自动生成巡检报告与设备履历。

### P2：形成企业运维平台

- 工单派发、排班、逾期和异常闭环。
- 说明书、图纸、维修视频和历史故障查询。
- 弱网离线巡检与恢复同步。
- OCR 识别铭牌、仪表读数和故障码。
- IoT 实时参数接入和阈值告警。
- 备件查询和领用记录。
- 专家会话转为知识条目或标准作业步骤。

### P3：硬件和项目驱动能力

- 热成像设备接入。
- 3D 模型和空间锚定指导。
- 复杂物体识别与数字孪生。
- 预测性维护和多源时序分析。
- 沉浸式培训与考核。

Air3 当前优先做屏幕级标注、二维码、OCR 和步骤指导。没有经过硬件验证前，不承诺稳定的空间锚定、热成像或高精度 3D 识别。

## 5. 录像功能建议

录像分两类：

- `任务证据短视频`：用户主动录制 15 秒至 2 分钟，关联设备和巡检步骤，优先实现。
- `专家通话录像`：录制整场音视频，需要参与者提示、权限、存储、上传、保留期和费用控制，后续实现。

不建议第一版默认录制整场专家通话。演示阶段先记录会话元数据、截图、标注和用户主动短视频，可以降低隐私、存储和 TRTC 录制费用风险。

## 6. 差异化机会

相比纯远程协作工具，叮当产品已有 626 的 AI 聊天、现场拍照、语音交互和项目记录，可以形成以下差异化流程：

1. AI 先根据设备资料、照片和语音进行初步诊断。
2. 无法处理时，带着完整上下文呼叫远程专家。
3. 专家标注和处理结论自动进入设备履历。
4. 重复问题沉淀为巡检步骤、知识条目或 AI 处理建议。

核心定位建议从“远程视频眼镜”升级为“AI 初诊 + 标准巡检 + 专家兜底 + 证据闭环”的设备运维终端。

## 7. 市场风险

- Microsoft Dynamics 365 Guides 和 Remote Assist 将在 2026-12-31 后停止提供，说明只绑定单一硬件和会议能力的产品路线风险较高。
- 企业客户通常要求私有化、权限、审计、离线和既有工单系统集成，演示版不能直接等同于生产版。
- 视频与录像会快速增加带宽、存储和合规成本，需要默认关闭整场录制并设置保留策略。
- 设备识别错误可能把证据挂到错误资产，二维码或人工确认必须优先于纯视觉自动判断。
