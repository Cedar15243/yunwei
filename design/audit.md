# V9 管理后台设计审计

目标：让管理员追踪眼镜现场任务、证据和同步异常，并能配置、验证、发布和分配真实可执行的现场工作流。

| # | 区域 | 问题 | 严重度 | 修复 | 工作量 |
|---|---|---|---|---|---|
| 1 | 信息架构 | 当前没有现场应用、工作流、版本或工单绑定入口，已完成的工作流 API 无法被管理员使用。 | 高 | 新增“现场应用”一级工作区，统一承载应用、流程、版本、发布与工单绑定。 | 大 |
| 2 | 编排 | 当前没有图形编排、节点属性、分支关系和 Air3 固定模板预览，无法验证企业自定义流程。 | 高 | 使用受控三栏编排器：目录/节点库、流程画布、属性与 HUD 预览；禁止任意网页代码。 | 大 |
| 3 | 真实性 | 页面缺少工作流的保存、服务端校验、签名发布、失败阶段和最终服务端结果。 | 高 | 所有写操作调用真实 API，区分草稿、校验、发布、冲突、无权限和签名不可用状态。 | 中 |
| 4 | 工作台 | “同步异常”只显示数量，无法直接定位失败任务或媒体。 | 高 | 增加失败媒体任务清单与进入任务详情的路径。 | 中 |
| 5 | 设备 | 设备页只读，管理员无法在受权工作流中签发或轮换设备凭据。 | 高 | 增加管理员专用凭据操作与一次性令牌确认对话框。 | 中 |
| 6 | 代码结构 | `App.tsx` 和多个页面使用压缩单行实现，继续堆功能会放大状态耦合和回归风险。 | 中 | 保持现有模块边界，将现场应用、流程编辑器、HUD 预览和 API 类型拆成独立文件。 | 中 |
| 7 | 数据状态 | 页面只覆盖加载、空和 API 错误，缺少局部重试与请求中的稳定占位。 | 中 | 为工作台、任务、媒体、设备和工作流查询增加局部重试与固定高度加载状态。 | 中 |
| 8 | 可访问性 | 导航使用链接模拟按钮，当前焦点状态不可见；状态色单独承担部分含义。 | 中 | 补齐 `aria-current`、键盘焦点环、按钮名称和文本状态，保持44px交互目标。 | 小 |
| 9 | 响应式 | 全局 `min-width:1080px` 让1024px设备直接溢出，三栏编辑器也缺少收缩规则。 | 中 | 桌面保持三栏，窄屏改为目录/画布/属性标签切换，不缩放文字或重叠控件。 | 中 |

结论：先完成1至3，形成可真实保存、校验和发布的现场应用工作台，再推进设备管理整改。完整读屏验证仍需人工辅助技术测试。
